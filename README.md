# Durion Positivity Frontend

Angular 22 single-page app for the Durion POS platform. It follows the workspace ADRs, uses Signals and lazy-loaded feature domains, and talks to the backend through the platform gateway.

## Quick Start

```bash
npm install
npm start
```

## Common Checks

```bash
npm run build
npm test
npm run lint
```

## Tenancy (ADR-0062)

The session's tenant comes from the access token's `tid` claim only; the gateway injects
`X-Tenant-Id` on every authenticated request and the browser never sends a tenant identifier.

- `environment.tenantHostSuffix` — host suffix that names the tenant (must match the gateway's
  `auth.tenant-host-suffix`). Served from `<slug><suffix>`, the login form shows the slug read-only
  and sends none; empty (localhost, shared preview hosts, alpha) puts the form in *form mode*: an
  optional tenant field is shown and sent as `LoginRequest.tenantSlug`. An unknown or inactive
  tenant gets the same bad-credentials message as a wrong password.
- `AuthService` exposes `tenantId()`, `tenant()` (slug, display name, status from
  `GET /security-service/v1/tenants/me`, kept across silent refreshes, cleared on logout) and
  `isPlatformTenant()`; the shell header shows the tenant next to the user.
- `/app/platform/tenants` is the tenant registry for platform operators (`platform:tenant:read`
  or `platform:tenant:create`, `ROLE_PLATFORM_ADMIN` fallback); `/app/admin/tenants` (the path the
  ADR-0062 plan names) redirects there. It calls pos-tenant through `ApiBaseService`
  with local models until the `@durion-sdk/tenant` package is generated by `API Artifacts Sync`.
- `mockAuth: true` binds the demo session to the platform tenant so these paths run in dev.
