# AGENTS.md — Durion Positivity Frontend

## Quick Start

```bash
npm install
npm start
npm run build
npm test
npm run lint                          # ESLint via @angular-eslint
npm run lint:css                      # stylelint src/**/*.css
npm run i18n:check                    # missing-keys + pseudo-locale check
npx ng test --no-watch --browsers=ChromiumHeadless --runner-config vitest.config.ts   # single CI pass (Vitest in Chromium; jsdom fails ~22 specs)
```

## Critical Rules

- Use Angular Signals for state and the generated `@durion-sdk/*` services, injected into a feature
  `services/` class, for backend calls (ADR-0041); `ApiBaseService` only where no SDK package exists yet.
- Follow the ADRs in `../durion/docs/adr/` before changing UI behavior or contracts.
- Keep translations in the locale files; no hard-coded user-facing strings.
- Prefer `routerLink` for in-app navigation and `takeUntilDestroyed`/`onCleanup` for reactive cleanup.
- Keep page state explicit and typed (`idle`, `loading`, `ready`, `error`).
- Tenancy (ADR-0062): the tenant comes from the access token's `tid` claim only. Never send a tenant identifier
  in a request body, query parameter, or header; never read one from a route. Platform-admin tenant and account
  pages consume `@durion-sdk/tenant` and are gated by `ROLE_PLATFORM_ADMIN`. The existing `organizationId`
  fields are a remnant; do not add new ones.
- Read `docs/EXEMPLARS.md` and the sibling services/pages of the domain you're touching before writing new
  code — reuse the shapes and helpers cited there instead of re-deriving them, and list the precedents you
  reused in the PR description.
- All six locale files under `src/assets/i18n/` gate together (`en-US`, `es-US`, `es-MX`, `fr-CA`, `fr-FR`
  hand-maintained; `qps-ploc` regenerated by `npm run i18n:pseudo:generate`, never hand-edited).
- SDK transport (ADR-0041): all calls to `durion-positivity-backend` go through the generated
  `@durion-sdk/*` Angular SDK, injected into a feature `services/` class. `ApiBaseService` is legacy
  migration infrastructure, not the canonical transport for new or modified backend calls; page/component
  code never composes a backend URL or calls `HttpClient` directly.
- `workorder` is one word everywhere — code, comments, docs, API text, logs (`workorder`, `Workorder`,
  `workorderId`, never `work order` / `WorkOrder`).

## Coding Patterns

Each pattern names its governing ADR; read `docs/EXEMPLARS.md` for the current file:line precedent
before reimplementing one from scratch.

### 1. Page state machine (ADR-0031 §1, §5)

`state` moves before `errorKey`, both into `'error'` and back out of it:

```typescript
error: () => {
  this.state.set('error');                        // REQUIRED — always first
  this.errorKey.set('DOMAIN.FEATURE.ERROR.KEY');   // REQUIRED — always second
},
// clearing back out — state still moves first:
this.state.set('ready'); this.errorKey.set(null);
```

### 2. Operational-board refusal toast (ADR-0031 §4)

A live, polling operational board may report a per-row write refusal via an assertive live region
instead of `state.set('error')`, only if it re-reads and `state()` stays `'ready'`:

```typescript
// run() error branch — does NOT call this.state.set('error')
this.refusalToast.set({ key: 'SHOPMGMT.DISPATCH.REFUSAL.CONFLICT', tone: 'error' });
this.reload(); // re-read so the board never contradicts the backend
```

Test asserts the key, the tone, the live-region role, and `state() === 'ready'` with rows interactive.

### 3. `effect()` loading with `onCleanup` (ADR-0033)

```typescript
effect((onCleanup) => {
  const id = this.selectedId();
  if (!id) return;
  this.state.set('loading');
  const sub = this.service.loadData(id).subscribe({
    next: (d) => { this.data.set(d); this.state.set('ready'); this.errorKey.set(null); }, // state first, then clear
    error: () => { this.state.set('error'); this.errorKey.set('DOMAIN.PAGE.ERROR.LOAD'); }, // ADR-0031 order
  });
  onCleanup(() => sub.unsubscribe()); // REQUIRED on every effect-body subscription
}, { allowSignalWrites: true });
```

Use `takeUntilDestroyed(this.destroyRef)` for subscriptions outside `effect()` (constructor,
`ngOnInit`, mutation handlers) — never as a substitute for `onCleanup` inside one.

### 4. Async result ownership (ADR-0063)

Capture request key/sequence at issue time; never re-derive them in the callback:

```typescript
private applySuccess(res: DashboardResponse, seq: number, key: string): boolean {
  if (seq !== this.readSeq) return false;  // WRONG if key/seq default to live signals
  this.dashboard.set(res); this.cachedKey.set(key);  // key the response ANSWERS
  return true;
}
```

One sequence counter per independent writer to a signal. Gate render/mutation on a
`hasCachedData`-shaped computed; settle pending guards/undo/toasts via an
`owedSettlements: Set<() => void>` drained by whichever read is current, including its failure branch.
Drive ordering tests through an RxJS `Subject`, never `of(...)`.

### 5. Read outcomes and placement vs. authorization (ADR-0064)

```typescript
map(rows => ({ states: toClockStateMap(rows), ok: true })),
catchError(() => of({ states: new Map<string, ClockState>(), ok: false })), // never a bare empty map
```

Keep a per-source `'PENDING' | 'OK' | 'FAILED'` status signal. Retained/stale data may say **where**
something sits, but actionability gates on the status being `'OK'`:
`clockIsActionable = computed(() => isViewingToday() && clockRead() === 'OK')`. A placeholder key
reachable from more than one cause must be true for all of them, or split into separate keys. Never
surface a raw UUID — fall back to `COMMON.NOT_AVAILABLE` or a feature `NOT_AVAILABLE_*` key.

### 6. Write-control gating (ADR-0040 §6a)

Gate the control **and** the method independently on the permission named in
`src/app/core/security/route-permissions.ts` — a read permission never enables a write:

```typescript
readonly canClearBay = computed(() =>
  !this.auth.permissionsKnown() || this.auth.hasAnyPermission(['workorder:position:assign']));

clearBay(bayId: string): void {
  if (!this.canClearBay()) return; // re-checked here, not only at the control
}
```

Undo/retry re-check permission and row state at click time, not when the action was armed. Tests cover
granted, denied (control disabled AND method refuses), the split between two authorities, and the
unknown-`perm_bits` case.

### 7. Dates (ADR-0038)

```typescript
function parseDateLocal(yyyyMmDd: string): Date {
  const [y, m, d] = yyyyMmDd.split('-').map(Number);
  return new Date(y, m - 1, d); // local midnight — never new Date(yyyyMmDd)
}
private readonly today = signal(startOfLocalDay(new Date())); // reactive: refreshed below, never read once
// on every poll tick (or a timer when the page does not poll):
this.today.set(startOfLocalDay(new Date()));
const dayAgo = new Date(now.getFullYear(), now.getMonth(), now.getDate() - 1); // local arithmetic, never ms subtraction
```

Tests derive today/yesterday from an injected or component-held date, never a literal or bare `new Date()`.

### 8. Server-generated fields omitted (ADR-0034)

```typescript
export interface LocationPriceOverride {
  readonly requestedAt?: string; // @serverGenerated — omit from create/update payloads
}
```

### 9. Typed fixtures (ADR-0032)

```typescript
const sampleMsrp: Msrp = { id: 'msrp-1', productSku: 'SKU-001', amount: 49.99, currency: 'USD', effectiveAt: '2026-01-01T00:00:00Z', endAt: null };
// never an untyped literal or `: any` — phantom fields must fail to compile
```

### 10. Untrusted content and storage keys (ADR-0065)

Untrusted text renders through a parsed token tree walked by Angular templates — never `[innerHTML]`
or `bypassSecurityTrust*`. Every URL is normalised (`normaliseHref`) then validated (`isSafeHref`)
before binding to an anchor/`[src]`/`[href]`. Tenant data in browser storage is keyed by `tid` **and**
`sub` together:

```typescript
private key(): string | null {
  const { tid, sub } = this.auth.currentUserClaims() ?? {};
  return tid?.trim() && sub?.trim() ? `${STORAGE_PREFIX}:${tid.trim()}:${sub.trim()}` : null;
}
```

### 11. Accessibility mechanics (ADR-0029 §8)

Native `dialog[appModalDialog]` for every modal, including nested (never `aria-modal` on a `div`); one
global `.sr-only` (`src/styles.css`), never redefined; hints via `aria-describedby`, never inside
the label of a control that carries an `aria-label`; `title` never the only channel; targets ≥24×24 CSS px; Label in
Name asserted per shipped locale; focus moved deliberately after any action that removes/replaces/
disables the focused control; live regions (`aria-live`, `role="alert"`) survive rebuilds; `aria-current`
vs `aria-selected` matched to the real widget type; toggle names describe the action, not the state;
visible `:focus-visible` on every control; list-item names carry their own identity; every drag
interaction has a keyboard equivalent.

### 12. i18n (ADR-0030)

Never call `translate.instant()` inside a `computed()`, a memoised `effect()`, or a field initializer —
the locale isn't a signal dependency, so the value freezes. Use the `translate` pipe in templates,
including for a value nested inside another key's interpolation param. Use `number`/`date` pipes for
locale-sensitive values. Assert copy claims against the real `src/assets/i18n/*.json` bundles
(ADR-0035 §8), not strings pasted into the spec.

## PR Checklist

### State & errors

- [ ] Every mutation `subscribe({ error })` calls `state.set('error')` immediately before `errorKey.set(...)`, both setting into error and clearing back out (ADR-0031 §1, §5)
- [ ] An operational-board write-path refusal uses an assertive live region + re-read, not `state.set('error')`; its test asserts the key, tone, live-region role, and `state() === 'ready'` (ADR-0031 §4)
- [ ] A primary-read failure routes through `state`/`errorKey` naming the actual condition; polling on a 403'd resource stops until a later load succeeds (ADR-0064 §6)

### Async & data

- [ ] Async apply functions take request key and sequence as explicit parameters, never re-derived from live signals; a signal written by two async sources has one counter per source or a documented shared coordinator (ADR-0063 §1–2)
- [ ] Rendering/mutation gates on a `hasCachedData`-shaped computed; a dialog/picker opened over a stale key closes or refuses on a key change (ADR-0063 §3)
- [ ] Pending guards, undo offers, focus restoration, and toasts are settled by whichever read is current on completion — success and failure — including a superseded or abandoned read (ADR-0063 §4)
- [ ] A poll/post-write readback refreshes every signal path the initial load populated, under the same guards; a tenant/subject identity change bumps every sequence and clears state first (ADR-0063 §5, §7)
- [ ] Browser-API callbacks (SpeechRecognition, timers, EventSource) check instance identity before mutating state, including deferred callbacks (ADR-0063 §6)
- [ ] Every degradable read returns `{ data, ok }` or a status union, never a bare empty array/map; a failed re-read keeps prior good data and flips only the status signal (ADR-0064 §1–2)
- [ ] 404-as-absence is caught only on the request whose contract documents it, never on an unqualified `forkJoin` leg (ADR-0064 §3)
- [ ] No placeholder key is reachable from more than one cause unless true for all; no raw UUID rendered as display text or an accessible name (ADR-0064 §4–5)
- [ ] Server-generated fields are `readonly?` in models and absent from create/update payloads (ADR-0034)

### Authorization

- [ ] Every mutation surface — button, drag/drop target, picker option, clear/× control, undo, keyboard shortcut, and the method body — gates independently on the write permission named in `route-permissions.ts`, matching what the backend endpoint actually enforces (ADR-0040 §6a.1–2)
- [ ] An unknown-`perm_bits` token follows the existing `canAccess()` legacy fallback, documented at the gate; undo/retry re-check permission and row state at click time (ADR-0040 §6a.3–4)
- [ ] Tests cover granted, denied (control disabled AND method refuses), the split between two authorities, and the unknown-claim case; a repointed permission gets an explicit negative test on the old code (ADR-0040 §6a.5)
- [ ] Docblocks/comments naming an authority are updated whenever the code changes — grep prose spellings too (ADR-0040 §6a.6)

### Accessibility

- [ ] Every modal (including nested) uses `dialog[appModalDialog]`, never `aria-modal` on a `div`; `.sr-only` is never redefined locally (ADR-0029 §8.1–2)
- [ ] Hints go through `aria-describedby`, never inside the label of a control that carries an `aria-label`; `title` is never the only channel; targets are ≥24×24 CSS px (ADR-0029 §8.3–5)
- [ ] Label in Name asserted against real locale bundles for every control with visible text; toggle names describe the action, not the current state (ADR-0029 §8.6, §8.10)
- [ ] Focus moves deliberately after any action that removes/replaces/disables the focused control; a visible `:focus-visible` ring is present on every control (ADR-0029 §8.7, §8.11)
- [ ] Live regions survive rebuilds; `aria-current`/`aria-selected` matched to the real widget type, no `aria-controls` on a conditionally-absent element; list-item names carry their own identity; every drag interaction has a keyboard equivalent (ADR-0029 §8.8–9, §8.12–13)
- [ ] Specs carry automated evidence axe cannot see: focus target, `dialog.matches(':modal')`, computed accessible names, live-region presence (ADR-0029 §9)

### i18n

- [ ] No `translate.instant()` inside `computed()`, a memoised `effect()`, or a field initializer; numbers/dates render through the `number`/`date` pipes, never manual formatting (ADR-0030)
- [ ] New keys exist in all six locale files; `qps-ploc` regenerated, never hand-edited
- [ ] Copy claims are asserted against the real `src/assets/i18n/*.json` bundles, not spec-local strings (ADR-0035 §8)

### Dates

- [ ] No `new Date(YYYY-MM-DD)` for local-date semantics — split and use `new Date(y, m-1, d)`; `DatePipe` is not applied directly to a raw `YYYY-MM-DD` string (ADR-0038 §1–3)
- [ ] A component comparing against "today" holds it as a signal refreshed on poll/timer, not computed once at construction; "today" boundary tests use local-time getters, not `toISOString()` (ADR-0038 §4, §6)
- [ ] Date-comparison specs derive today/yesterday/rolled-over-day from an injected or component-held date, never a literal or bare `new Date()`; day/week bucketing uses local calendar arithmetic, never fixed 24-hour millisecond subtraction (ADR-0038 §7–8)

### Tests

- [ ] Every public `*Service` method has ≥1 test: an `ApiBaseService`-backed method asserts HTTP verb + URL + the success emission; an SDK-backed method asserts the generated facade call's full argument list + the success emission (see `docs/EXEMPLARS.md` §8); fixtures are typed against the exact domain interface — no `any`, no untyped literals (ADR-0032, ADR-0035 §1, §9)
- [ ] A load-bearing test for every new guard/branch/negative case is shown to fail when the guard is reverted, then restored — state this was done in the PR description (ADR-0035 §5)
- [ ] Ordering/race/settlement tests drive the async dependency through an RxJS `Subject`, never `of(...)`; both halves of a behavioral split are asserted, including the negative branch (ADR-0035 §6–7, ADR-0063 §8)
- [ ] A service method calling the SDK with positional arguments has a test asserting the full argument list (ADR-0035 §9)

### Navigation

- [ ] Every in-app navigation link uses `routerLink` (with `RouterLink` in the component's `imports`), not bare `href`; every retry/reload/action control is a `<button>`, not an `<a>` (ADR-0037)

### Security & tenancy

- [ ] The tenant comes from the access token's `tid` claim only — never sent in a body/query/header/route (ADR-0062)
- [ ] Untrusted text renders through a parsed token tree — no `[innerHTML]`, no `bypassSecurityTrust*`; every URL bound to an anchor/`[src]`/`[href]` is normalised then validated, and the rendered value is the normalised one (ADR-0065 §1–2)
- [ ] A client-generated CSV/TSV cell from untrusted content is formula-lead-prefixed before RFC 4180 quoting; an object URL from a triggered download is revoked with a deferred call, not synchronously after `.click()` (ADR-0065 §3)
- [ ] A browser storage key for tenant data derives from both `tid` and `sub`, never `sub` alone; an in-memory identity guard compares `tid|sub` together (ADR-0065 §4–5)
- [ ] A stored value is validated field by field on read and a malformed entry is filtered out, never thrown; writes enforce a bounded size/count budget and a quota failure is caught, not silently lost (ADR-0065 §6)

### Description honesty

- [ ] No checkbox is ticked that wasn't actually performed — an unticked-in-reality checkbox is worse than an honest gap; every claim in the description is re-verified against the final diff right before the last push
- [ ] Docblocks/comments naming a behavior, authority, or field are updated when it changes, including prose spellings, not only literal identifiers; no configuration/flag/field is added that nothing in the codebase reads

### Validation commands run locally

- [ ] `npm run build`, `npx ng test --no-watch --browsers=ChromiumHeadless --runner-config vitest.config.ts`, `npx ng lint`, `npm run lint:css`, `npm run i18n:check`

CI now runs the same set in `.github/workflows/frontend-checks.yml` (plus `.github/workflows/accessibility-gate.yml`) — a local pass before pushing catches failures before the gate does; it does not replace it.

## Common Mistakes

| Mistake | Why it is wrong | Do this instead | Rule |
| --- | --- | --- | --- |
| `applySuccess(res, key = this.requestKey())` | Defaults to the live controls at callback time, caching the response under whatever's on screen when it lands, not what it answered | Pass `key`/`seq` explicitly, captured when the request was issued | ADR-0063 §1 |
| Clearing a pending guard on any landing read | A superseded read can clear a guard whose real write is still in flight, or leave it stuck forever if its own read loses the race | Clear only on the current read; park the obligation in `owedSettlements` otherwise | ADR-0063 §4 |
| One sequence counter shared by two writers to a signal | An unrelated write (e.g. a clock re-read) can invalidate and discard a concurrent enrichment read | One counter per independent writer, or a documented shared coordinator | ADR-0063 §2 |
| `catchError(() => of(new Map()))` on an enrichment read | Makes an outage and a genuinely empty answer the same value | Return `{ data, ok: false }` and keep a `PENDING/OK/FAILED` status signal | ADR-0064 §1 |
| A placeholder key naming one cause when the sentinel is reachable from several | The copy asserts a cause the read never confirmed | Split into one truthful key per cause, or verify the key is true for all reachable causes | ADR-0064 §4 |
| `aria-modal` on a `div` | Implements nothing — no focus trap, no top-layer promotion, no Escape handling | Use `dialog[appModalDialog]` | ADR-0029 §8.1 |
| `.sr-only` redefined per component | Scoping it locally silently breaks if the selector doesn't match, rendering labels visibly | Use the single global `.sr-only` in `src/styles.css` | ADR-0029 §8.2 |
| Hint text placed inside the label of a button that carries an `aria-label` | `aria-label` replaces descendant text in the accessible name — the hint is never announced | Attach the hint via `aria-describedby` pointing at a separate id | ADR-0029 §8.3 |
| `BREAK_END_ARIA` not starting with the visible label in fr/es | Fails Label in Name (SC 2.5.3) for a speech-input user in that locale | Assert Label in Name against every shipped locale bundle, not just `en-US` | ADR-0029 §8.6 |
| Focus lost (falls to `<body>`) when its control is removed | A keyboard/screen-reader user loses their place with no announcement | Move focus deliberately after the readback that removes the control | ADR-0029 §8.7 |
| `translate.instant()` inside a `computed()` | The locale isn't a signal dependency, so the value freezes at whatever language was active when it first ran | Use the `translate` pipe in the template | ADR-0030 |
| `{{ hours }}` with no `number` pipe | Renders unformatted, locale-incorrect grouping/decimals | `{{ hours \| number: '1.0-1' }}` | ADR-0030 |
| A route read permission enabling a write control | Violates read/write separation — the backend endpoint enforces a different, narrower authority | Gate the control and method independently on the named write permission | ADR-0040 §6a.1 |
| `of(...)` stub in an ordering/race test | Resolves synchronously, so the guard under test never observes the "pending" state | Drive the async dependency through a `Subject` | ADR-0035 §6 |
| Copy assertions against strings pasted into the spec | Drifts silently when the real bundle changes; a key-echo test isn't a copy test | Load the real `src/assets/i18n/*.json` bundles in the spec | ADR-0035 §8 |
| `new Date()` for "today" computed once at construction | Stale after a local-midnight rollover while the page stays open | Hold today as a signal refreshed on the page's poll/timer | ADR-0038 §6 |
| A test with a literal date string (`new Date('2026-09-17')`) | Expires — passes today, fails on every day after | Derive today/yesterday from an injected or component-held date | ADR-0038 §7 |
| Browser storage keyed by `sub` only | A subject switching tenants can read the previous tenant's stored data | Key by `tid` AND `sub` together | ADR-0065 §4 |
| `//evil.example/...` passing a scheme allowlist | A protocol-relative URL carries no scheme, so an allowlist checking only scheme lets it through as if same-window | Reject network-path references (`//`, `\\`) before the scheme allowlist | ADR-0065 §2 |
| RFC 4180 quoting alone on a CSV cell from untrusted content | Stops delimiter injection, not formula execution (`=HYPERLINK(...)`) | Prefix a formula-lead cell (`=+-@`, tab, CR) before quoting | ADR-0065 §3 |
| PR checklist item ticked but not actually performed | Misleads reviewers and erodes the checklist's value as evidence | Leave it unticked, or perform the check before ticking it | Description honesty |

## Review Loop

Read Copilot review bodies for a "Suppressed comments" section before responding — it lists findings
that were filtered from the visible thread but still apply. After two rounds of incremental fixes, do
one whole-diff adversarial pass rather than a third incremental patch, then push once. Cite the ADR
number in every review reply that accepts, defers, or disputes a finding.
